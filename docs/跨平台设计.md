实际做法和下文原来的设计有几处不同，原因写在对应的小节里：Linux 的路径不看 XDG 变量；Linux 桌面上的密码也先存文件；tun 模式自己设路由和分流 DNS，sing-tun 的自动路由和 DNS 接管都关掉；systemd 单元用自己的模板。

## 现状：哪些已经跨平台，哪些只适用于 macOS

已经跨平台、能直接用的：

| 部分 | 依赖 | Linux | Windows |
|---|---|---|---|
| VPN 端点、分流、本地代理、状态接口 | sing-box | 能用 | 能用 |
| 后台服务 | kardianos/service | systemd（用户级和系统级都有）、OpenRC、SysV | 只有系统服务（LocalSystem），没有用户级 |
| 存密码 | zalando/go-keyring | Secret Service（要有 gnome-keyring 或 KWallet，经 D-Bus） | 凭据管理器 |
| 设置系统代理 | sing-box `common/settings` | GNOME（gsettings）、KDE（kwriteconfig5/6），别的桌面不支持 | WinINet，只对当前用户生效，必须在用户自己的会话里设 |
| tun 网卡 | sing-tun | 能用 | wintun，DLL 已经内嵌，不用另装驱动 |
| 直连用的系统解析器 | Go 标准库 | glibc / systemd-resolved | Windows 的 DNS 接口 |

只适用于 macOS、要按平台重写的：

| 部分 | 现在的位置 | 说明 |
|---|---|---|
| 配置、日志、服务文件的路径 | `config.go`、`cmd_service.go` | `~/Library/…`、`/Library/…` |
| status 里检查系统代理 | `cmd_setup.go` 的 `scutil --proxy` | 别的平台直接返回「不知道」 |
| tun 的分流 DNS | `tun_darwin.go`，写 `/etc/resolver/<后缀>` | Linux 和 Windows 是空实现，setup 直接拒绝 |
| 问密码前关回显 | `echo_darwin.go` | 别的平台不关，退回原来的行为 |
| 打开网页面板 | `cmd_service.go` 的 `open` | |
| 说明文字 | README、提示语里的 LaunchAgent、钥匙串等字眼 | |

还有一点要提前说：sing-tun 在 Linux 上只要没关 DNS 模式（`dns_mode`），就会用 `resolvectl domain <网卡> ~.` 把整台机器的 DNS 交给 tun（`tun_linux.go:359`、`1216`），和开没开 auto_route 无关。我们只接管学校域名，所以要关掉它这一步，改成自己设置。

## 代码怎么组织

每个平台一个文件，实现同一组函数，编译时按平台选（Go 的 `_darwin.go`、`_linux.go`、`_windows.go` 惯例）。这一组函数是：

- 路径：配置目录、日志目录。
- 服务：装、卸、启、停、查状态。macOS 和 Linux 交给 kardianos，Windows 的 system 和 proxy 模式另写，见下文。
- 系统代理现在指向哪：status 和 setup 用。
- 分流 DNS：tun 启动时设、退出时撤。
- 关回显、打开浏览器。

不另外抽一层接口：现在已经有 `tun_darwin.go` 和 `tun_other.go`，照这个样子扩展就行。

## 各平台怎么做

### 路径

| | macOS | Linux | Windows |
|---|---|---|---|
| 配置（proxy、system） | `~/.config/sidedoor` | `~/.config/sidedoor` | `%APPDATA%\sidedoor` |
| 配置（tun） | `/Library/Application Support/sidedoor` | `/etc/sidedoor` | `%ProgramData%\sidedoor` |
| 日志（proxy、system） | `~/Library/Logs/sidedoor` | `~/.local/state/sidedoor` | `%LOCALAPPDATA%\sidedoor\logs` |
| 日志（tun） | `/Library/Logs/sidedoor` | `/var/log/sidedoor` | `%ProgramData%\sidedoor\logs` |

日志都写文件，不用 journald 或 Windows 事件日志。这样截短日志、status 里给出日志路径这些逻辑，所有平台都一样。

Linux 原来打算跟着 `XDG_CONFIG_HOME`、`XDG_STATE_HOME` 走，实际没有：systemd 起服务时不带登录 shell 里设的这些变量，按它们算出来的路径，setup 写的和后台服务读的会对不上，比如密码文件。所以固定用这两个变量的默认位置。

### 后台服务

- **Linux**：
  - proxy、system 模式用 systemd 用户服务，登录后启动。服务器上没人登录，要 `loginctl enable-linger` 才能开机就跑，setup 会提示。
  - tun 用系统级 unit。
  - 单元名是 `sidedoor.service`。kardianos 负责装、卸、启、停，但单元文件用自己的模板：它自带的那份日志用 `file:`（每次启动从开头往上覆盖），挂了要等 120 秒才重启，用户服务也挂在 `multi-user.target` 上（用户级 systemd 里没有它，开机和登录都不会启动）。自己的模板用 `append:`、`Restart=always`、`RestartSec=10`，用户服务挂在 `default.target` 上。
  - 只测 systemd，OpenRC 和 SysV 不保证。
- **Windows**：proxy、system 模式用登录时运行的计划任务，tun 模式用 Windows 服务，见 D1。

### 存密码

- Linux 桌面：原来打算用 Secret Service，实际先和服务器一样存文件：开机就启动的用户服务常常赶在钥匙串解锁之前。等做 Linux 桌面支持时再看要不要改。
- **Linux 服务器（没有 Secret Service）**：存成只有本人能读的 0600 文件，tun 模式是 root，见 D2。
- Windows：proxy、system 模式用凭据管理器；tun 模式的服务以 SYSTEM 身份运行，读不到用户的凭据，存在 `%ProgramData%\sidedoor` 下只有管理员和 SYSTEM 能读的文件里。

### system 模式：系统代理

- **Linux**：
  - 只支持 GNOME 和 KDE，这是 sing-box 的范围。
  - setup 检测不到这两种桌面时，不列出 system 模式，推荐 proxy 或 tun。
  - status 检查分两种：GNOME 用 `gsettings get org.gnome.system.proxy mode`，KDE 用 `kreadconfig`。
  - 命令行程序在 Linux 上只看 `http_proxy` 这类环境变量，system 模式管不到它们，README 里写明。
- **Windows**：
  - WinINet 设置是每个用户各自的，sidedoor 必须在用户的会话里运行，这一点决定了 D1。
  - status 检查读 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`。

### tun 模式：分流 DNS

macOS 的做法是只把学校域名的查询交给 sidedoor（`/etc/resolver/<后缀>`），其余 DNS 不碰。另外两个平台要找对等的机制：

- **Linux**：systemd-resolved 分流，见 D3。网卡固定叫 `sidedoor0`，sing-tun 的 `auto_route` 和 `dns_mode` 都关掉：前者在 Linux 上会加一整套 `ip rule`，后者会接管整台机器的 DNS。网卡建好之后自己加一条假 IP 段的路由，再用 `resolvectl` 设路由域 `~<后缀>`、关掉 default-route、DNS 指向网卡上的假 DNS。启动前检查 `/etc/resolv.conf` 交给了 systemd-resolved，判断方法和 sing-box 的 local 一致：这样 sing-box 解析 VPN 服务器自己的名字时只问默认网卡的 DNS，不会被 resolved 转回自己。
- **Windows**：NRPT 规则，见 D4。

两个平台的路由都和 macOS 一样，只把假 IP 段 `198.51.100.0/24`（加上网卡自己的 `192.0.2.0/30`）路由进网卡，不接管默认路由。

## 定下来的取舍

每一项的第一个选项是选中的方案，后面的是比较过、没有采用的。

**D1 Windows 后台怎么跑**：
- **选定** A：proxy、system 模式用「登录时运行的计划任务」，在用户自己的会话里运行，能设 WinINet，失败可以设成自动重启；tun 模式用 Windows 服务（SYSTEM 身份，能建网卡、改 DNS 策略）。
- B：全部用 Windows 服务，另在用户会话里跑一个小助手负责设系统代理。要做两个进程之间的通信，复杂得多。
- C：用注册表的 Run 键自启。最简单，但进程意外退出后没人拉起来，不像 launchd 的 KeepAlive。

**D2 Linux 服务器上的密码**：
- **选定** A：和 macOS 的 tun 模式一样，存成只有本人（tun 模式是 root）能读的 0600 文件。做法一致，任何发行版都能用。
- B：systemd-creds 加密存储，绑定本机密钥。更安全，但要较新的 systemd，复杂度也高。

**D3 Linux tun 的分流 DNS**：
- **选定** A：用 systemd-resolved，给 tun 网卡设 DNS `192.0.2.2`、路由域 `~cuhk.edu.cn`，并设 `default-route false`。只有学校域名的查询会过来，和 macOS 的 `/etc/resolver` 是同一个思路。Ubuntu、Fedora、Debian 12 默认都有 systemd-resolved；没有的系统上 tun 模式不可用，提示改用 proxy。
- B：把 `/etc/resolv.conf` 的 DNS 全部指向 sidedoor，非学校域名由 sidedoor 再转给原来的 DNS。所有发行版都能用，但接管了全部 DNS，sidedoor 一挂整台机器都解析不了。

**D4 Windows tun 的分流 DNS**：
- **选定** A：NRPT（名称解析策略表），给 `.cuhk.edu.cn` 加一条规则指向 `192.0.2.2`，卸载时删掉。这是 Windows 原生的按域名分流 DNS 机制，和 macOS 的 `/etc/resolver` 对等，需要管理员权限，tun 模式本来就要。
- B：把 tun 网卡的 DNS 设成最高优先级，所有查询都先到 sidedoor，非学校域名再转出去。接管了全部 DNS，风险和 D3-B 一样。
