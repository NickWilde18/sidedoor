# sidedoor 手动测试计划

## 怎么用

- 按编号顺序做。风险从低到高排：T0–T5 不改任何东西；T6–T11 会断开学校连接、切换模式；T12（tun 模式）和 T13（卸载）会改系统设置、删配置，放在最后，可以不做。
- 每一项做完，在下面的记录表里填 ✅ 或 ❌。不符合预期时，把命令的完整输出贴出来；输出里如果有状态接口的密钥，可以打码。
- 中途出问题，先看文末的「出问题怎么恢复」。

## T0 准备

1. 装上最新版本：`cd ~/Repo/sidedoor && git pull && make install`
2. `sidedoor status`

**预期**：后台服务「运行中」，隧道「已连接」，模式是 system，系统代理「已指向 127.0.0.1:11080」。

## T1 日常访问（system 模式）

1. 在浏览器里打开一个**只有连上学校 VPN 才能访问**的学校系统，用你平时会用的那个。
2. 再打开一个普通网站，比如 github.com。
3. 打开一个 Tailscale 机器的地址，比如 `http://emberbound.tail5cd230.ts.net:61208/`。这类名字只有 Tailscale 的解析器认识，之前经过 sidedoor 会 502。
4. `sidedoor status`

**预期**：
- 三个地址都能正常打开。
- 「流量」里「走 VPN」的下载量比 T0 时多了；「VPN 连接」里出现这个学校系统的域名。
- 普通网站和 Tailscale 地址都不出现在「VPN 连接」里。

## T2 网页面板

1. `sidedoor dashboard`
2. 浏览器打开之后，不手动填任何东西。
3. 看 Overview 页的流量曲线，再点 Conns 页。
4. 在后台列表里，把 `127.0.0.1:9090` 那一条删掉。

**预期**：
- 面板直接连上，不会停在「Connect to a backend」。
- Overview 页的曲线在动。
- Conns 页能看到学校域名的连接，规则一栏是 `domain_suffix=cuhk.edu.cn => route(vpn)`。

## T3 停止和启动

1. `sidedoor stop`
2. 打开「系统设置 → 网络 → Wi-Fi → 详细信息 → 代理」。
3. 分别打开 T1 里的学校系统和普通网站。
4. `sidedoor start`
5. 再打开 T1 里的学校系统。

**预期**：
- 第 1 步输出「✓ 后台服务已停止」和「✓ 系统代理已还原」。
- 第 2 步看到网页代理、安全网页代理、SOCKS 代理全部关闭。
- 第 3 步普通网站能打开，学校系统打不开。这一步顺便证明了那个学校系统确实需要 VPN。
- 第 4 步依次输出「✓ 后台服务已启动」「✓ 隧道已连接」「✓ 系统代理已指向 127.0.0.1:11080」。
- 第 5 步学校系统又能打开了。

## T4 完整运行一遍新版 setup

1. `sidedoor setup`
2. 第 2 步直接回车，选推荐的 system。
3. 第 3 步：服务器地址直接回车，沿用上次的值；GROUP 直接回车；然后输入用户名和密码。
4. 第 4 步直接回车。

**预期**：
- 输出 `[1/5]` 到 `[5/5]` 五个步骤。第 1 步会先停掉正在运行的服务。
- 第 5 步依次输出：配置已写入、密码已存入系统钥匙串、后台服务已安装、隧道已连接、系统代理已指向。
- 最后列出带编号的「接下来」。
- GROUP 只问了一次，「服务器说：…」那句提示也只出现一次。

## T5 setup 中途取消

1. `sidedoor setup`
2. 走到问密码的时候，按 Ctrl-C。
3. `sidedoor status`

**预期**：Ctrl-C 之后输出「✓ setup 没有完成，已恢复原来的后台服务」；接着在同一个终端里随便打几个字，**字能显示出来**（问密码时关掉的回显已经恢复）；status 显示运行中、已连接。

## T6 setup 时输错一次密码

只输错**一次**，不要连续输错，免得触发学校账号锁定。

1. `sidedoor setup`，到问密码时故意输错一个字符。
2. 看服务器返回什么，然后按提示重新输入正确的密码，把 setup 走完。

**预期**：输出「! 服务器提示：…」（服务器给的登录失败原因），然后重新问一遍密码；输入正确后正常走完。

## T7 睡眠唤醒后自动重连

1. 确认 `sidedoor status` 显示已连接。
2. 合上盖子，或者从苹果菜单选「睡眠」，至少等 10 分钟。
3. 唤醒后记下时间，每隔 30 秒运行一次 `sidedoor status`，直到隧道显示「已连接」。
4. 如果超过 2 分钟还没连上，运行一次：`dig +time=2 +tries=1 @100.100.100.100 www.cuhk.edu.cn`

**预期**：一般 1–2 分钟内重新连上。第 4 步是为了区分原因：如果 `dig` 超时，说明是 Tailscale 的 MagicDNS 还没恢复（今天实测就是这样，拖了 6 分钟）；那种情况下整台电脑的 DNS 都会受影响，不只是 sidedoor。请在备注里记下"唤醒到连上"一共用了多久。

## T8 切换网络

1. 切到另一个网络，比如手机热点，或者拔插网线。
2. `sidedoor status`
3. 打开 T1 里的学校系统。
4. 切回原来的网络，重复第 2、3 步。

**预期**：每次切换后，隧道都能自己重新连上，而且「系统代理」一行仍然显示「已指向 127.0.0.1:11080」。sing-box 会把系统代理设置到新的默认网卡上；如果这里显示没指向，说明它没有跟着新网卡走。

## T9 重启电脑后自动启动

1. 重启电脑。也可以只注销再重新登录。
2. 登录后什么都不做，等 1 分钟。
3. `sidedoor status`

**预期**：后台服务运行中，隧道已连接，系统代理已指向。

## T10 系统代理被别的工具抢走

1. 打开 Shadowrocket 并连接。
2. `sidedoor status`
3. 断开 Shadowrocket。
4. `sidedoor status`。如果这时系统代理仍然不对，运行 `sidedoor restart` 再看一次。

**预期**：
- 第 2 步「系统代理」一行显示「! 现在指向 127.0.0.1:1082，不是 sidedoor」。
- 第 4 步恢复为「已指向 127.0.0.1:11080」。请在备注里写一下，是断开 Shadowrocket 后自动恢复的，还是 restart 之后才恢复的。

## T11 proxy 模式配合 Shadowrocket

1. `sidedoor setup`，第 2 步选 `1`（proxy），其余照 T4 的做法。
2. 打开 Shadowrocket，使用之前那份 cuhksz.conf（`CUHK-SZ = socks5, 127.0.0.1, 11080`）。
3. 在浏览器里打开 T1 里的学校系统。
4. `sidedoor status`
5. 恢复成 system 模式：先断开 Shadowrocket，再运行 `sidedoor setup` 并选 `2`。

**预期**：
- 第 1 步结束时没有修改系统代理的那一行，「接下来」第 1 条提示你去代理工具里配置转发。
- 第 3 步学校系统能打开。
- 第 4 步模式显示 proxy，「走 VPN」的流量在增加，「VPN 连接」里有学校的域名。

## T12 tun 模式（可选，风险最高）

这一项会修改路由表和 `/etc/resolver`，需要输入电脑的开机密码（sudo）。先通读一遍「出问题怎么恢复」再开始。

**前提**：Shadowrocket 已断开。Tailscale 保持开着，正好测试和它共存。

1. 停掉普通模式的服务，腾出端口：`sidedoor stop`
2. `sudo sidedoor setup -mode tun`，照 T4 的做法走完。
3. `sudo sidedoor status`
4. 查看它改了哪些东西：
   ```sh
   cat /etc/resolver/cuhk.edu.cn
   scutil --dns | grep -A3 "domain   : cuhk.edu.cn"
   netstat -rn -f inet | grep 198.51.100
   ```
5. 查一个学校域名的解析结果：`dscacheutil -q host -a name www.cuhk.edu.cn`
6. **不经过代理**直接访问：`curl -sS -o /dev/null -w "%{http_code}\n" --noproxy '*' https://www.cuhk.edu.cn/zh-hans`
7. 在浏览器里打开 T1 里的学校系统；打开普通网站；确认 Tailscale 照常可用。
8. 还原：
   ```sh
   sudo sidedoor uninstall
   ls /etc/resolver/
   netstat -rn -f inet | grep 198.51.100
   sidedoor start
   ```

**预期**：
- 第 3 步模式显示 tun，隧道已连接。
- 第 4 步：
  - resolver 文件第一行是 `# sidedoor 生成，停止时删除`，下一行是 `nameserver 192.0.2.2`；
  - `scutil --dns` 里出现指向 `192.0.2.2` 的 `cuhk.edu.cn` 解析器；
  - 路由表里有一条 `198.51.100/24` 走某个 `utun` 网卡；
  - **除此之外没有别的新路由**。
- 第 5 步解析出来的是 `198.51.100.x`，这是 sidedoor 发的假 IP。
- 第 6 步返回 200。
- 第 7 步学校系统、普通网站、Tailscale 都正常。
- 第 8 步 uninstall 逐条报告删除了什么；之后 `/etc/resolver/` 里没有 `cuhk.edu.cn`，路由表里没有 `198.51.100`；`sidedoor start` 之后又回到 system 模式，并且已连接。

## T13 卸载和重装（可选）

1. `sidedoor uninstall`
2. 逐项检查：
   ```sh
   ls ~/Library/LaunchAgents/ | grep sidedoor
   security find-generic-password -s sidedoor
   ls ~/.config/sidedoor
   ```
   再打开「系统设置 → 网络 → Wi-Fi → 详细信息 → 代理」看一眼。
3. 重新装上：`sidedoor setup`

**预期**：
- 第 1 步逐条报告：服务已卸载、系统代理已还原、密码已删除、配置已删除。
- 第 2 步：三条命令都找不到东西（`security` 那条会说 "could not be found"），三个系统代理都是关着的。
- 第 3 步和 T4 一样能顺利装好。

## 出问题怎么恢复

- **所有网页都打不开**：运行 `sidedoor stop`。如果还是打不开，到「系统设置 → 网络 → Wi-Fi → 详细信息 → 代理」把三个代理都关掉。
- **tun 模式出问题**：运行 `sudo sidedoor uninstall`。如果这条命令本身就报错，按下面手动清理：
  1. `sudo launchctl bootout system/com.nickwilde.sidedoor`
  2. `cat /etc/resolver/cuhk.edu.cn`，确认第一行是 `# sidedoor 生成`，然后 `sudo rm /etc/resolver/cuhk.edu.cn`
  3. 虚拟网卡和它的路由会随进程一起消失，不用手动处理。
- **想看后台在做什么**：日志在 `~/Library/Logs/sidedoor/com.nickwilde.sidedoor.err.log`，tun 模式在 `/Library/Logs/sidedoor/`。
